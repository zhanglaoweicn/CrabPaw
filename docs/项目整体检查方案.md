# CrabPaw 项目整体检查方案（无死角版）

- **项目**：CrabPaw (v2.2.0) — 多通道 AI 助手平台，Electron+React GUI + Node 后端
- **方案日期**：2026-08-28
- **适用范围**：仓库全量（`src/` 后端、`gui/` 前端、`evals/`、`plugins/`、`skills/`、`data/`、`docs/`、`scripts/`、`test/`、构建产物、CI 配置、依赖清单）
- **原则**：分层递进、动静结合、交叉印证、安全优先；先静态后运行时、先后端后前端、先主链路后分支；每次改动以「测试/契约」收口，不留未验证断言。

---

## 一、总体原则

1. **零假设**：不为文档/注释的声明担保，凡声明必须读到「文件:行号」证据。
2. **动静结合**：静态（AST/正则/扫描）+ 动态（运行/契约测试/Playwright/实跑 eval）互为印证。
3. **三层口径**：`文档声明` / `实现` / `实测` 三者比对，任何不一致即记录。
4. **安全与破坏面**：所有检查只读或带隔离；写操作（增删改/自愈/删除/执行）必须走 mock 或显式确认，避免污染生产数据。
5. **可追溯**：每条发现带定位（文件:行号）+ 证据 + 影响 + 建议，汇入可执行清单。
6. **回归收口**：任何修复都以「对应测试/契约 100% 通过」为完成标准。

## 三、分阶段执行计划

### 阶段 0｜准备与基线（0.5 天）
- 冻结版本、备份工作区（`git status` 干净基线）。
- 确认环境：Node 版本、`npm ci` 成功、后端可启动、GUI 可跑。
- 记录现有基线：`node evals/index.js` 通过率（当前 **99.8% 417/418**）、契约测试、单测数量、覆盖率。
- **产出**：基线报告，后续检查与之对比（防止回归由本次引入）。

### 阶段 1｜静态质量（D1 + D11 部分，1 天）
1. `npm run lint`（eslint src/ --ext .js）+ `gui npm run typecheck`（tsc --noEmit）→ 0 error（warning 记录）。
2. 死代码/未引用导出扫描：Node 脚本遍历 `export`/`module.exports`，grep 被引用数=0 的组件（已发现 `buildCompactPrompt`、`createTrajectoryHooks`、`createDefaultMiddlewareChain`、轨迹 cleanup 等）。
3. 空 catch / 未处理 Promise：grep `catch {}`、catch 未打日志 → 补 `console.error`。
4. 命名规范：契约 PascalCase（已发现 2 个 kebab-case 违规）、变量/文件命名一致性。
5. 循环依赖：madge `--circular` → 有向无环优先。
6. 文档一致性：契约数/评估数/技能数/版本/行号/路径 交叉核对（见 D11）。

### 阶段 2｜前后端对齐（D2，1–1.5 天）
1. 端点存在性：跑 `frontend-routes.contract.test.js`（5/5）+ `api-routes.contract.test.js`。
2. 载荷/响应结构：脚本提取前端 `apiGet/Post/...` 与后端各 handler 期望字段，逐一比对；重点核对「扁平 vs data 包裹」陷阱（已发现 CommodityPanel `res.items` vs `res.data.items`）。
3. SSE/WS 事件名：前端订阅名 ↔ 后端 `broadcastEvent` 名全量比对（activity/turn_complete/*/filegen:*/meeting:*/collab:*/skill:*/approval_*/workflow:*/scene:change 等）。
4. 运行时 404/500：Playwright 加载 GUI + 遍历各页/tab，抓取所有响应，标记非 2xx。
5. **验收**：对齐契约测试全绿 + 运行时无意外 4xx/5xx。

### 阶段 3｜运行时功能（D3，1.5–2 天）
1. 后端：冷启动 → `/health` 200；逐组探测只读接口（GET /status、/config、/api/* 只读）返回结构正确。
2. GUI 渲染：Playwright 逐页/逐 tab 截图 + console 错误捕获（管理舱 8 tab、设置各 section、记忆、状态、日志、技能、专家、插件、用量、调试）。
3. 实时链路：SSE `/events`（activity/turn_complete/heartbeat/scene:change）、WS `/voice/cloud`、WS `/scene` 连通与事件流。
4. 端到端主流程（每一流程一个最小闭环，尽量走 mock 或只读）：
   - 对话：发送 → SSE 流 → 工具调用 → 回复结束
   - 任务：触发任务 → roundId/flowId 聚合 → 完成/错误/中断
   - 技能：执行 → skill:started/completed/error
   - 专家/协作：collab 开始 → progress → completed/error/timeout
   - 审批：请求 → 批准/拒绝
   - 面板：打开→数据→关闭→状态同步
5. **验收**：核心主流程全部跑通；异常分支（错误/取消/超时/中断）有明确处理。

### 阶段 4｜业务逻辑（D4，1–1.5 天）
- 逐流程走读 + 状态机核对，重点（已初筛）：
  - 会议转写分段排序（>9 乱序）、`getFullTranscript` 死逻辑
  - CollabOrbit `timeout` 收口（永久 running 卡）
  - TaskPanelHost 订阅名 vs 广播名（tool_call）
  - 面板 open/close 的 panel-state 对称性（schedule/knowledge 缺 open；typhoon 键未注册）
  - task-panel-store 按 roundId/flowId 聚合、workflow_step 忽略 stepId
  - 空数组/undefined/NaN/超长回退的边界
- 对每处逻辑，构造输入验证（用单测或 Node 脚本跑状态机函数）。
- **验收**：每个状态机有单测覆盖且通过；边界用例不抛未捕获异常。

### 阶段 5｜安全（D6，1.5 天）<重点专项>
1. 鉴权：`auth-middleware`/`/auth/bootstrap`/`X-Api-Key`/token；`PUBLIC_ROUTES_BY_METHOD` 只读 + webhook 出入（已有契约）→ 补：越权/未授权访问 `/api/*` 应 401/403。
2. 输入注入：SSRF（skill-market 抓取、webhook、fetch 代理）、SQLi（nl2sql/db）、命令注入（Bash/ShellExec）、XSS（Markdown 渲染/HtmlGenerate）。
3. 危险命令：Safety Hooks 拦截 `rm -rf /`、`mkfs`、`dd if=`（harness-hooks.js）→ 实测触发即拦截。
4. 密钥处理：secret 脱敏（`redactSensitive`、`maskSecret`）、config 掩码回填（`'***'`）、日志不泄 key；SetupWizard `'none'` 占位 key 落地检验。
5. 文件权限：`path-rules.js` DEFAULT/PLAN/FULL_AUTO 三种模式 → 越权读写/执行是否阻断。
6. 依赖漏洞：`npm audit --production` + 全量 `npm audit`；sherpa/electron 等 native 组件审计。
7. **验收**：安全契约/渗透用例全绿；无高危 vuln（≥1 需处理）；危险命令/越权/注入均被拦截。

### 阶段 6｜性能与可靠性（D7，1 天）
- 指标：metrics-pipeline（LLM/tool p50/p95/p99、token、错误分类）+ dashboard 导出校验。
- 内存：长会话/大上下文 heap 曲线（health-monitor）；memory/kb 大数据量下是否泄漏。
- 并发/竞态：多请求并发（voice 双 WS、SSE 9 订阅者单连接）是否串扰；`lastLarkSenderId` 全局变量 vs 请求级 sender 的竞态。
- 超时：LLM/tool/proxy 超时与 abort 语义（ApiTimeoutError）是否贯穿。
- 自愈：SelfHealing/RecoveryChain/健康监控 → 故障注入（mock 失败）验证恢复。
- **验收**：无未捕获泄漏；p95 在可接受范围；并发场景无错乱；故障可自愈。

### 阶段 7｜数据与存储（D8，1 天）
- 库存根：SQLite / MySQL / PG 连接、schema 完整、迁移脚本可执行。
- 一致性：memory（unified/notebook）、knowledge base、trajectories、audit（JSONL）、任务/会话存储，写入读取一致。
- 备份/恢复：`/api/backup/create|restore|list` 演练（隔离数据），确认可恢复。
- 数据目录：`data/` 下 `.crabpaw`、`skills/`、`projects/` 等路径与实际写入一致（已发现轨迹双 `.crabpaw` 嵌套）。
- **验收**：备份可恢复；一致；迁移无破坏。

### 阶段 8｜测试覆盖 / CI / 回归（D9，1 天）
- 全量测试：`npm test`（jest，src/test）、`gui vitest run`、e2e（playwright）。
- 覆盖率：`npm test -- --coverage`（CI 已配）→ 关键模块（ai.js、tool-orchestrator、budget-enforcer、loop-detection、panel/scene、task）覆盖率阈值。

- CI：`.github/workflows/ci.yml` 三阶段（lint→test→eval）本地复现跑通；分支保护 required 检查清单。
- 回归基线：`eval:regression --baseline v3`。
- **验收**：测试全绿 + eval 100% + 覆盖率达标 + CI 本地复现为绿。

### 阶段 9｜依赖 / 构建 / 发布（D10，1 天）
- `npm audit`（见 D6）；锁定版本（package-lock）一致。
- 构建全链路：`gui build:vite`、`gui build`（electron-builder）、`build:portable`；`npm run build:release`。
- 打包产物：`CrabPaw-Release/`、portable，产物体积/依赖完整（extraResources 中的 node/sherpa/python）。
- 冷启动安装检测：`postinstall` / `@electron/rebuild`（sherpa-onnx-node native）成功。
- **验收**：构建全链路成功；产物可运行；无缺失依赖。

### 阶段 10｜配置 / 发布 / 文档收口（D11 + D12，1 天）

## 四、跨维度一致性交叉检查（防「各自为政」）

- **文档↔实现↔实测**：同一指标三方比对（D1/D11/D2/D9 联动）。
- **前端↔后端↔契约**：任何前端调用必须可解析到后端路由且载荷一致（D2），并由运行时实测兜底（D3）。
- **架构↔代码**：HARNESS 8 维度声明必须能在代码中找到接线与消费（D5），凡声明无消费方即标注死代码。
- **安全↔鉴权↔数据**：危险写操作必须过 Safety/PathPermission 钩子（D6）且落数据目录白名单（D8）。
- **CI↔回归↔门禁**：CI 使用与本地一致的命令；门禁与回归基线一致（D9）。
