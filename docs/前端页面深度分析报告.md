# CrabPaw 前端页面深度分析报告

- **项目**：CrabPaw (v2.2.0) 前端（Electron + React + Vite + TypeScript）
- **检查日期**：2026-08-28
- **范围**：`gui/src/`（pages / components / hooks / lib / contexts / types）、构建产物、运行时渲染
- **方法**：结构盘点、静态质量（tsc/包体）、运行时渲染（临时纯 web Vite + Playwright 遍历主界面与管理舱各 tab）、错误/警告捕获、源码定位

---

## 一、总体结论

前端**功能主体健康、结构清晰**（类型检查 0 错误、主界面与管理舱 tabs 可渲染、SSE 单连接复用、组件化程度高），但发现 **1 个显著的整页 UX 缺陷、1 个 React key 缺陷、若干性能/工程配置缺口**。最重要的是技能管理页的**中文文案以字面 `\uXXXX` 转义显示**——这是会导致整个页面可读性崩溃的真实 bug。

## 三、静态质量

| 检查 | 结果 |
|---|---|
| `tsc --noEmit`（gui） | ✅ **0 TS 错误** |
| 构建产物 | 总 **7.5MB**；主 chunk `index-*.js` **812KB（gzip 前）**、`vendor-three` 510KB、`vendor-ui` 213KB、`vendor-markdown` 116KB、`vendor-mermaid` 63KB |
| ESLint | ⚠️ **gui 无 ESLint/Prettier 配置**（package.json 仅有 `typecheck`；根目录 eslint 仅覆盖后端 `src/ --ext .js`，不检查 `gui/**.tsx`） |

- 主 chunk 812KB + three 510KB 对 Electron 可接受但偏重；建议对 three/mermaid 做按需/懒加载（当前管理舱总览/成本用到了 mermaid/katex，但 VoiceShell 主屏未必需要 three）。
- **工程配置缺口**：gui 缺 ESLint/Prettier，CI 的 lint 阶段目前只跑后端 `.js`，不覆盖前端 `.tsx`。新增 AGENTS.md 提到 CI 含 `gui-test`，但 `ci.yml` 实际只有 lint→test→eval 三步（无 gui-test job）——文档与 CI 不一致（见 §六）。

## 五、真实缺陷（重点）

### 🔴 缺陷 1：技能管理页整页中文以 `\uXXXX` 转义显示（严重 UX）
- **文件**：`gui/src/pages/SkillsManagement/index.tsx`（**47 处**字面量 `\uXXXX`）
- **现象**：标题、说明、下拉选项、placeholder、aria-label、按钮文案等全部显示为 `\u6280\u80fd\u7ba1\u7406`（技能管理）、`\u52a0\u8f7d\u4e2d…` 之类，页面几乎不可读。
- **根因**：代码把中文写成了 **JSX 裸文本** 或 **JSX 属性字符串**（如 `<h2>\u6280\u80fd\u7ba1\u7406</h2>`、`title='\u5237\u65b0'`、`placeholder='\u641c…'`）。**JSX 不解释 `\uXXXX` 转义**（只有 `{'\u6280\u80fd'}` 这种 JS 字符串字面量才解码），因此这些文本按字面渲染成背斜杠 u 序列。
- **影响**：仅此页；但整页中文全部失效，属明显回归。
- **修复**：把 JSX 裸文本/属性字符串里的 `\uXXXX` 替换为真实中文字符（或包成 `{'\uXXXX'}` JS 表达式）。

### 🟠 缺陷 2：ExpertReviewCard 重复 React key
- **文件**：`gui/src/components/SceneShell/kinds/expert-review.tsx`（经 `CollabOrbit/index.tsx` 渲染）
- **现象**：React 警告「Encountered two children with the same key」。轨道卡列表因 key 冲突出现重复/丢弃。
- **关联**：与此前发现的 CollabOrbit「按 archetype+LIFO 匹配、忽略 taskId」一致，多专家并行时轨道卡会错配/重复。
- **修复**：为轨道卡列表提供稳定唯一 key（优先 taskId/expertId）。

### 🟡 缺陷 3：畸形媒体 URL
- `https://upos.direct.mp4/` `ERR_NAME_NOT_RESOLVED`——疑似媒体/B站解析在失败或空结果时生成了残缺地址。建议在请求/解析处对「空/异常 url」做校验降级。

## 六、工程与配置观察

- **gui 缺 ESLint/Prettier**：前端 `.tsx` 无自动 lint；建议补 `@typescript-eslint + eslint-plugin-react + prettier` 并纳入 CI。
- **CI 一致性**：AGENTS.md（更新后）写 CI = `lint → test → gui-test → eval`，但 `ci.yml` 实际只有 lint→test→eval（无 gui-test job）。gui 的 `typecheck`/`test:e2e` 未接入 CI lint/测试阶段——需确认并按文档补齐。
- **`npm run dev` 耦合 electron**：gui 用 `vite-plugin-electron`，`npm run dev` 会同时构建并拉起 electron 主进程；在无 GUI/无头环境 electron 无法启动（`electron.app undefined`），导致整个 dev 进程退出。做纯前端开发/浏览器调试需**剥离 electron 插件**（我本轮即用临时纯 web 配置实现）。建议提供 `dev:web` 独立脚本。
- **构建产物**：7.5MB / 主 chunk 812KB；three/mermaid 建议懒加载；gui 有自己的 package-lock（依赖独立），CI 需单独处理。

## 七、可访问性 / UX 观察

- 大量使用 `aria-label`/`title`（意图良好），但技能页因 `\uXXXX` 全部失效——本轮修复后需复核。
- 图标化（lucide-react，0 `<img>`），加载/空/错误态在各面板均有覆盖（如「暂无技能」「加载失败·重试」），体感不错。
- 一致性问题：`总览`tab 快照为空、`连接`/`用量`显示 loading——个别 tab 数据加载时序较高，建议加骨架屏/超时提示。

## 十、补充深度分析（二次复核）

> 本节的第二次深审聚焦前端自身：架构/类型安全、错误处理、隐私日志、XSS 面、记忆化、健壮性、测试覆盖。前述 §一~§九 结论均已在此轮复核确认未变（技能页 `\uXXXX` 仍在 47 处、ExpertReviewCard 重复 key 仍存在、gui 仍无 ESLint、CI 仍无 gui-test）。

### 10.1 架构/类型安全：广泛依赖 `window as any` 全局通信（重点）
- **规模**：`window as any` 达 **266 处**；`any` 全库 **876 处**；`@ts-ignore` **0 处**（无 TS 压制，正面）。
- **现象**：组件与 Hook 之间大量通过 `window.__xxx` **全局可变状态**通信：
  - 语音/TTS 会话标志：`__ttsActive`、`__ttsSessionSeq`、`__speechQueuePlaying`、`__voicePlayActive`、`__voiceSessionId`、`__asrReconnects`、`__voiceResumeTTS`、`__voiceInterruptTTS`、`__ttsAnalyser` 等（`useVoiceReply`/`useVoicePlayConsumer`/`useSpeechQueue`/`useVoiceSession`/`VoiceIntegration`/`useContinuousVoice` 多写多读）。
  - 面板宿主句柄：`__cockpit`、`__sceneShell`、`__schedulePanel`、`__filePanel`、`__meetingPanel`、`__knowledgePanel`、`__weatherPanel`/`__hotspotPanel`/`__typhoonPanel`/`__stockPanel`、`__mediaStage`、`__skillStage`、`__avatarHost` 等。
- **问题**：这是**全局状态反模式**——跨模块耦合、并发写同一 `__tts*` 标志存在**竞态**、`any` 化导致类型不可靠、难以单测/复用。
- **已部分缓解**：`lib/ui-command-registry.ts:4` 自注「旧架构: 各宿主组件挂载时写 (window as any).__weatherPanel = {...} 等全局句柄」，引入了注册表抽象（`ui-command-registry`）来替代面板句柄的裸全局；`CommandPalette` 已用该注册表。但**语音/TTS 的跨 Hook 标志仍未走注册表/统一 store**。
- **建议**：将语音/TTS 跨 Hook 状态收敛到统一 store/context（如 VoiceStateContext 已存在，可扩展）；继续推进面板句柄到 `ui-command-registry` 的迁移；对残留 `window.__xxx` 用 `any` 收紧为白名单类型。

### 10.2 静默吞错
- `VoiceShell/index.tsx:268` `apiPost('/config', {...}).catch(() => {})` —— 配置保存失败**静默吞掉**，无 warn/用户提示。属自愈路径但仍应记录。
- `StockPanel/index.tsx:481` 定时刷新 `.catch(() => {})` —— 刷新失败静默。
- `useSoundEffects.ts:65` `resume().catch(() => {})` —— 可接受（fire-and-forget）。
- **建议**：对业务写操作（保存/刷新）失败至少 `console.warn` 或 toast。

### 10.3 隐私与日志噪音
- `console.log` **112 处**，多数带前缀/`DIAG_ON` 门控（可接受）。但：
  - TTS 日志把老板的**语音内容文本段**打进 console：`[TTS] playNext: seg="%s"`、`[TTS] prefetch hit: ...`、`[TTS] playTTSViaHttpGet: GET URL (text=%d chars)`。
  - `Settings/index.tsx:459/465` 打印 `wecom.botId.substring(0,8)`（部分标识）。
  - `VoiceShell/index.tsx:1250` 打印语音搜索文本 `q`。
- **建议**：移除/门控输出**内容类**日志（含 TTS 转写文本、搜索词、botId），仅保留长度/状态摘要；对外发布默认关 `DIAG_ON`。

### 10.4 XSS 面：已较好控制（正面）
- `dangerouslySetInnerHTML` 3 处，均安全：
  - `FilePreviewModal` → `sanitizeHtml`：**DOMParser 白名单**（非纯 regex），含属性白名单、`on*` 事件属性全拦截、危险协议检查（剥 C0 控制字符 + **仅允许 data:image/png|jpeg|gif|webp**（已移除 SVG））、reverse tabnabbing（强制 rel=noopener）、属性转义——**健壮**。
  - `FileGenPanel.highlightLine`：**先 HTML 转义**（`&<>`）再做语法高亮——安全。
  - `CollabOrbit`：`<style>` 使用硬编码常量 CSS——安全。
- 结论：未发现明显 XSS 向量。

### 10.5 记忆化与性能
- `useCallback/useMemo/memo` 共 **290 处**——记忆化**充分**（正面）；仅 `MemoryGraph` 用了 `React.memo`（1 处）。
- 包体 7.5MB / 主 chunk 812KB / `vendor-three` 510KB（已在 §三 记录）；建议对 three/mermaid 懒加载。
- 建议：对高频重渲染的列表组件（如 EventLog、任务面板、专家列表）补 `React.memo`。

### 10.6 健壮性/边界
- `lib/top-overlay.ts:29` 读 `document.documentElement` 时**无守卫**（在测试/非 DOM 环境抛 `Cannot read properties of undefined" 且 `documentElement"）。已在该模块测试中暴露；建议加 `typeof document === 'undefined'` 守卫。
- 大量 `setInterval/setTimeout`（127 处引用），多在 useEffect 内带 cleanup（如 Gateway/Status/Logs/ExpertsPanel/MeetingPanel 均有 clearInterval），但仍有部分需核对（如 `AgentLeftPanel.tsx:125`、`useVoiceReply` 内多个 interval 位于异步回调——建议统一 ref + cleanup 核对）。

### 10.7 前端测试覆盖（D9）
- `gui` 有大量 vitest 单测（`src/**/*.test.{ts,tsx}`），本次运行可见 **20+ 套件通过**（top-overlay / web-preview / useAgentMonitor / task-panel-store / collab-orbit / holo-phase / agui-chat-normalize / orb-config / attachment / cockpit-navigation / SideSheet geometry 等）。
- **注意**：本次 `npx vitest run` 在输出最终汇总前被**中断**（退出码 `0xC000013A`，即 STATUS_CONTROL_C_EXIT），未得出「Tests N passed」的明确总数——疑有测试长时间挂起或总时长超限。建议单独跑一遍全量 vitest 并排查挂起用例。
- 结论：前端有良好单测基座，但**全量 vitest 是否全绿待确认**——这是 D9 前端覆盖的一个未决项。

### 10.8 补充结论
- 二次深审最实质的新发现是 **`window as any` 全局通信架构**（泛用、竞态、难测）与 **内容类日志的隐私/噪音**；其余（静默吞错、top-overlay 无守卫、仅 1 个 memo）为低危。
- 未修改任何源码；临时 vite 配置/脚本/截图已清理；vite 临时服务已停止。
