## 三、问题根源

### 根源 1: 记忆提取靠正则，不是 LLM

```javascript
// memory-capture.js 当前做法
this.importantPatterns = [
  /我(喜欢|爱|偏好|想要|希望)/gi,  // ← 正则匹配
  /我的(名字|职业|公司)/gi,         // ← 只能捕获固定句式
];
```

问题：能捕获"我是程序员"，捕获不了"我干这行十年了，一直在写后端"。

### 根源 2: 记忆之间没有"关系"

```
当前: 记忆 = 一堆独立的 JSON 文件/数据库行
缺失: 记忆A"关联"记忆B, 记忆A"矛盾"记忆C, 记忆A"是"记忆D的更新
```

### 根源 3: memoryExtraction.js 是空壳

```javascript
// 整个文件就这点有效代码
extract(conversation) {
  return [];  // ← 永远返回空。什么都没提取。
}
```

这个文件本来应该负责"从每轮对话中自动提取重要信息"，但它什么都不做。

### 根源 4: 没有 LLM 参与记忆管理

当前的记忆系统所有操作都是规则引擎（正则、阈值、计时器）。LLM 只在 `active-memory.js` 的搜索阶段参与，不在提取/关联/矛盾检测阶段参与。

## 四、优化方案

### Phase 1: 修复空壳 — memoryExtraction 复活

**改动文件**: `memoryExtraction.js`

**做法**: 让 `extract()` 真正干活。每轮对话后，用一个轻量 prompt 让 LLM 从对话中提取：

```javascript
extract(conversation) {
  // 让 LLM 从对话中提取:
  // 1. 用户偏好 (喜欢/不喜欢什么)
  // 2. 事实信息 (姓名/职业/项目)
  // 3. 待办事项 (用户提到的"下次要...")
  // 返回结构化数据
  return llm.extract(conversation, EXTRACTION_PROMPT);
}
```

**影响**: 这是最大的单一改进。之前所有记忆都靠正则漏掉 80%，修了这个大部分记忆会自动入库。

### Phase 2: 记忆关联 — 建立关系图

**新建文件**: `memory-relations.js`

**做法**: 当新记忆入库时，自动检查：
1. 是否与已有记忆相矛盾？（"用户是程序员" vs "用户是设计师"）
2. 是否是已有记忆的更新？（"预算 10 万" → "预算 20 万"）
3. 是否与已有记忆相关？（"项目A的预算"和"项目A的进度"）

**影响**: 记忆从一个"列表"变成一个"网络"。这是记忆从"被动"到"主动"的关键一步。

### Phase 3: 矛盾检测 + 主动追问

**做法**: 当 Phase 2 检测到矛盾时，在回复中温和提醒：
- "你提到预算是 20 万，但我记得之前你说是 10 万——需要更新一下吗？"

**影响**: 用户感觉到系统"真正在听"。

## 六、关键发现

**memoryExtraction.js 是空壳**——这是记忆系统不智能的根因。

这个文件本应负责"从每轮对话中自动提取重要信息并存入记忆"，但它什么都不做。修这一个文件 = 修复了记忆系统 80% 的"不智能"问题。

其他文件（decay、archiver、active-memory）都是正常的，只是它们依赖的"提取"环节是断裂的。
