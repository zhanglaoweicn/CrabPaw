## 0. 一句话目标

让这台机器在**老板对客人说一句话**的场景里，既显得厉害、又看得懂；并且在 95% 的**待机时间**里就像一台值钱的东西。

**边界（本方案不做）**：不改语音链路（ASR/TTS/唤醒）、不改打包与自启、不把屏幕做成时钟/壁纸应用、不新增"档位开关"（模式已经三档，够多了）。

---

## 1. 目标场景的三个角色

| 角色 | 要什么 | 现在屏幕给了吗 |
|---|---|---|
| **老板** | 一句话进去，屏幕立刻有反应、有结果——要"显得厉害" | 有反应，但结果是一串 10px 小卡，不"厉害" |
| **客人**（围观者） | 看懂"刚才发生了什么" | 看不懂：字号小、过程是内部工具名 |
| **环境**（待机） | 老板开口**之前**就先赢——客人进门先看到它 | 没赢：起步是暗球 + 三块说"没事"的玻璃卡 |

技术设定按部署手册：**1–2m 观看距离、触摸一体机、无键盘、全屏无边框**。

## 2. 现状体检

### 2.1 A 类：视觉与结构（已在实机/代码核对）

1. **emoji 六处**：📟 日志 / 💬 对话 / ◉ 心跳 / ◉ 要办的事 / 📦 今日产出 / ☀ 今日（外加 🦀 品牌头）。这是"专业仪器 → 手机 App"的头号降级项。
2. **主角太小**：球固定 250px，1920 宽屏上占屏宽 **13%**；周围三块卡与它等高。挂墙 1–2m 看，球只有指甲盖大。
3. **默认态字号 10–13px**：日志卡 10–10.5px、卡片标签 9–11.5px、顶栏图标 13px。客人该读懂的东西没有一件达到 1–2m 可读的标准。
4. **卡片语言是"深色后台"**：1px 边框 + 半透明填充 + 小标签，是 2019 年以来的通用暗色 SaaS 面板语言。科幻感来自**光/运动/尺度**，不是面板数量——现在靠"加卡"表达信息，方向反了。
5. **三带平分重心**：左列卡 / 中球 / 右对话，三条竖带各占一份注意力。
6. **起步画面一半在说"没事"**：左列三张卡里，「要办的事」空态是"现在没有要办的事"、「心跳」是"已就绪 · 主服务已连接"、「日志」是"3 条日志 · 0 次工具"。**屏幕最贵的左上角在汇报一切正常。**
7. **辉光没跟状态走**：`AmbientGlow` 写死 `accent="purple"`、强度固定 1/1.4。这是最省钱的"影院效应"：球在想 → 整面墙琥珀，在说 → 变蓝，1–2m 外不看字就知道它在干活。
8. **私密信息上墙**：晨报带会把"应收逾期 N 笔 ¥X + 客户名"直接列在屏幕上。工位上是贴心，**客人在场是当着外人晾应收账款**。

### 2.2 B 类：文档与代码的落差（本轮新发现，最要紧）

这三条直接决定"老板对着一体机说一句话"能不能成立：

1. **触摸 PTT 不存在**。部署手册 §4 写"按住屏幕中央的语音球说话，松手即发"，但代码里 PTT **只有空格键**（`gui/src/components/VoiceIntegration.tsx:300`、`:356`），`OrbTopBlock` / `VoiceOrb` / `usePushToTalk` 里**没有任何 pointer/touch 处理**（已 grep 确认）。一体机没键盘 → 唯一能"按着球说话"的路径缺失。
2. **球上唯一的触摸动作是"静音"**：`OrbTopBlock` 的球按钮 `onClick={onToggleMute}`。客人伸手点球，期望"它开始听我"，实际**把麦克风关了**。
3. **kiosk 只做了窗口层**：`--kiosk` → `win.setKiosk(true)` + `powerSaveBlocker`（`gui/electron/main/window-mode.ts`），**渲染层收不到 kiosk 信号**——所以手册 §4 的"字号加大到 16/15px"、§5 的"待机态只留小尺寸呼吸的球"在 UI 上都没有实现。后来的「演示模式」（藏遥测 + 放大正文）是同一意图的部分实现，但它**手动触发**（顶栏一个 13px 图标），且不与 kiosk 联动。

> 结论：**这个场景现在是"文档上像做完了、代码里没做"**。第一批就该补这个缺口。

## 3. 设计原则

1. **减法优先**：科幻感从"删掉盒子"来，不从"加特效"来。每一批都应让屏幕上的元素**变少、变大**。
2. **待机态是主角**：屏幕 95% 时间在待机，而"酷"是在老板开口**之前**赢的。待机不是"没内容"，是一张**环境显示器**（时间 / 今天要事 / 呼吸的球）。
3. **一个焦点**：球是唯一主角，信息绕着它排（弧线/外环/下方一行），不再左右两条竖带。
4. **运动要有意图**：三种即可——呼吸（待命，极慢）、响应（在听/在想/在说，有方向）、事件（完成/审批到达：一次由球向外的脉冲波）。不叠加无意义循环动画。
5. **不牺牲务实**（硬约束，不可回归）：审批到达必须可见、零输入必须有信息、闸门（tsc + 全量单测 + precommit）必须绿。

### 反模式（明确不做）

- 霓虹渐变、扫描线、`> SYSTEM ONLINE` 之类伪终端文案——会把"高级"瞬间降级成"廉价游戏 UI"。
- 为了酷而加档位开关（`simple / advanced / present` 已经三档，再加会让"我该用哪档"成为新问题）。
- 把客人该读的结果藏进悬停/展开。

## 4. 需要你拍板的 5 件事（方案依赖它们，建议先定）

| # | 问题 | 我的建议 |
|---|---|---|
| P1 | 待机时球能否"呼吸"？（2026-08-24 你定过「关闭 = 完全静止的珍珠」） | 保留"显式关麦 = 完全静止"；**待机（开着麦只是没人说话）允许 2% 极慢呼吸**——1–2m 外静止的球读起来像卡死/屏保 |
| P2 | 球上的手势语义 | **按住 = 说话（PTT）、单击 = 开始听 / 打断播报、长按 = 静音**。现在单击=静音，在触摸一体机上反直觉且危险 |
| P3 | 客人面前是否显示"逾期应收 / 客户名 / 金额" | **默认隐藏明细**，只留"今天 3 件事 · 1 件等你拍板"；明细进会客厅模式的屏蔽名单 |
| P4 | 一体机是不是触摸屏？ | 若是（手册按触摸写的），触摸 PTT 属必修；若不是，则改为"远场唤醒词 + 大字号提示"路线，方案 S1 减一项 |
| P5 | 上一轮我提的三处球体配色 | 蓝亮端提亮（现在蓝/绿明度太近，投屏分不出在听/在说）、橙暗端降饱和（长时间思考像警示灯）、要不要加第五态"待批准"琥珀慢脉冲（产品决策） |

## 5. 分批方案

### S1 「会客厅地基」四刀 —— 1 天，收益立刻可见

| 刀 | 做什么 | 动哪里 |
|---|---|---|
| ① kiosk 信号进渲染层 | 主进程把 `kiosk/fullscreen` 经 preload 暴露给渲染层，据此进入"会客厅 UI 态" | `gui/electron/main/window-mode.ts`、`gui/electron/preload`、新增 `useKioskMode` |
| ② 触摸 PTT | 球加 pointer 手势：按住说话（松手发）、单击打断/开始听、长按静音；热区 ≥44px，`touch-action: manipulation` | `OrbTopBlock/index.tsx`、`VoiceIntegration`（PTT 触发源从"仅空格"扩为"空格或触摸"）、`usePushToTalk` |
| ③ 球放大 | 会客厅态球尺寸由"固定 250"改为"屏高 ×45%（clamp 320–560）"；工位态不变 | `VoiceShell/index.tsx`（`OrbTopBlock size`）、styles.css |
| ④ 去 emoji | 六处 emoji 换 lucide 线性图标，尺寸 18–20px（工位态同步受益） | `SysInfoCard`、`ChatInputArea`、`VoiceShell`、`MorningBriefingStrip` |

**验收**：一体机上按住球说话能出结果（不需要键盘）；1920 宽下球占屏高 ≥40%；全屏截图里 emoji 数 = 0；闸门绿。

### S2 「待机态当主角」—— 1–2 天

- 待机画面 = 球（呼吸）+ 状态词 + 一行操作提示（"说'小龙女'或按住球说话"）+ **一行大字要事**（如"今天 3 件事 · 1 件等你拍板"，28–36px；时间/日期次要）。
- **空的内容一律不占位**：`要办的事` 仅 `pending > 0` 时出现；`心跳 + 日志` 合并成球旁一个状态点/细条，**只在异常或进行中出现**（离线/重连中/工具执行中）；对话卡保持"一开始对话就展开，之后可收成小胶囊"（现状已是）。
- **验收**：完全无数据时首屏可见元素 ≤ 4（球 / 状态词 / 提示 / 要事行）；有待办时待办出现且不遮球；审批到达 1 秒内可见（不可回归）。

### S3 「会客厅模式」（把演示模式升级并跟 kiosk 联动）—— 1–2 天

- `--kiosk` 启动 → **自动进入会客厅态**（现在的演示模式要手点）；退出需要显式操作。
- 整体 UI 缩放 ×1.5–1.6（正文 20–24px、客人该读的结果 28–32px、按钮热区 ≥44px）。
- **私密信息脱敏**（P3 定案后）：隐藏逾期明细/客户名/金额，只留计数与"等你拍板"。
- 入口：顶栏从 13px 图标提到显眼位置 + 语音直达（"打开会客厅模式/投屏模式"）。
- **验收**：1–2m 距离下客人能读懂结果卡；客人视角截图里没有客户名与金额；进入/退出不影响主对话（不可回归）。

### S4 「高光时刻」—— 2 天

- 执行叙事：球收缩（被吸住）→ 环绕扫描弧 → **结果以大字卡落下**（"会议纪要已生成 · 3 页"，32px 起）→ 球回到待命。
- 工具细流（10px 工具卡列表）**只在工位态显示**，会客厅态收进"正在执行"一行。
- **验收**：录屏给非技术同事看，他能说出"刚才它做了什么"。

### S5 「材质与声音」—— 2 天

- 去盒子：信息不再装在 1px 边框卡里；用发光细分隔线/弧线分段；只在"活动元素"上给光边。
- **辉光跟随状态色**（三行改动）：`AmbientGlow` 的 accent 由球态决定（听=绿 / 想=琥珀 / 说=蓝），强度随音量与思考进度呼吸。
- 声音补齐：唤醒上扬音已有；补"开始执行"低音垫与"任务完成"确认音（复用 `useSoundEffects`）。
- **验收**：关掉文字层，只看球与辉光，能分清四种状态。

## 6. 验收口径（可测）

1. **可读性**：1920 宽全屏截图，客人该读懂的字 ≥28px；正文 ≥20px。
2. **待机体面度**：完全不交互时截图给外人看 5 秒，判断"像不像一台值钱的东西"。
3. **无字状态辨识**：遮住所有文字，只看球 + 辉光，能否分清 待命/在听/在想/在说。
4. **单手势直觉**：无讲解时，第一次触摸屏幕的人会做对事（现在是点了球 = 静音）。
5. **过程可复述**：非技术旁观者能用自己的话复述"刚才发生了什么"。

**不可回归**（每批都要守）：审批到达可见、零输入有信息、tsc 0 错、86 套件 893 用例 + precommit 五项全绿。
