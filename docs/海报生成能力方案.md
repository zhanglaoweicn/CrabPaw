# 海报生成能力方案（面向中小企业老板）

> 2026-09-08 设计提案 · 状态：待评审开工
> 目标客户：中小企业老板。三类刚需：产品/业务宣传海报、节日营销海报、客户问候海报。

---

## 一、为什么"直接用 Seedream 出海报"不行（设计出发点）

AI 生图对**中文营销文案**的致命短板：电话号码、价格、日期、门店地址这类"一个字都不能错"的内容，Seedream/所有生图模型都会写错字。营销海报错一个数字就是事故。

开源界的共识也证明了这一点——主流开源海报项目（msgposter、markdown-to-image、qfui-aigc-poster-builder、deepseek-zhipu-poster-generator）**全部采用"AI 生成 HTML/CSS → 浏览器渲染 → PNG"的确定性排版路线**，AI 只负责装饰性内容，不负责精确文字。

因此本方案的核心架构是**双层渲染**：

```
底层：Seedream 生成无文字的底图/产品场景插画（AI 擅长）
        ↓
上层：HTML 模板 + 真实文案 + 品牌色 → 无头浏览器截图（文字 100% 精确）
        ↓
成品 PNG（按平台规格）
```

## 二、开源生态结论（问题 1 的回答）

| 项目 | 思路 | 对本方案的价值 |
|---|---|---|
| [gcui-art/markdown-to-image](https://github.com/gcui-art/markdown-to-image)（1.6k★） | Markdown→精美海报图 | 排版模板思路 |
| [anonymous5l/msgposter](https://github.com/anonymous5l/msgposter)（555★） | Markdown→社交海报 PNG | 轻量渲染管线 |
| [sunqifly/qfui-aigc-poster-builder](https://github.com/sunqifly/qfui-aigc-poster-builder) | AIGC+Agent：MD→多套 HTML 海报布局（Vue3/Tailwind） | **模板+AI 组合模式最接近本方案** |
| [CardinalOperations/PosterCraft](https://github.com/CardinalOperations/PosterCraft)（286★） | 10 万+真实海报训练的美学生成流水线 | 美学评估思路（重，不直接集成） |
| [23305340/SmartPoster](https://github.com/23305340/SmartPoster)（193★） | ComfyUI+ChromaDB 设计 agent，175+ 资产 | 设计意图分解思路（ComfyUI 依赖太重） |

**结论：不引入任何重框架**（ComfyUI/扩散模型依赖与现有架构冲突）。开源界验证了"HTML 模板+数据+浏览器渲染"这条路线，我们自建轻量模板层——而且 CrabPaw 已有无头浏览器（playwright-core）、Seedream、filegen 卡片状态机三大件，自建成本最低。

## 三、核心设计：品牌资产包 + 双层渲染 + 文件卡工作流

### 3.1 品牌资产包（Brand Kit）——对老板最大的价值

中小企业老板最缺设计师，最需要"每次都像同一个品牌"。一次性录入、终身复用：

```json
// data/workspace/brand-kit.json（设置页可维护）
{
  "companyName": "XX机械设备有限公司",
  "logo": "data/workspace/brand/logo.png",
  "slogan": "二十年机械制造专家",
  "colors": { "primary": "#C8102E", "secondary": "#1B2A4A" },
  "contact": { "phone": "400-xxx-xxxx", "address": "XX市XX区XX路", "wechat": "xxx" }
}
```

每张海报自动携带品牌一致性：主色系、logo 位置、联系方式落款、字体规范。

### 3.2 海报工作流（复用 filegen 状态机 v2，新增 format: 'poster'）

```
①需求理解   海报类型/主题/平台尺寸（不足时 Clarify 追问）
②文案与素材  LLM 写卖点文案；可选 WebSearch 查节日/行业资料；
            业务库取产品/客户数据（DatabaseQuery）
③底图生成   Seedream：按主题+品牌色生成无文字底图（比例=平台规格）
④排版合成   HTML 模板（节日/产品/问候 × 模板库）+ Brand Kit + 文案 + 底图
            → playwright-core 截图 → PNG
⑤多规格变体  朋友圈 1:1 / 公众号 2.35:1 / 小红书 3:4 / 抖音 9:16 一键多规格
```

状态机、SSE 事件（filegen:start/phase/done）、卡片 UI、取消/恢复/追问、产物注册——**全部复用现有 filegen v2**，海报只是一种新的 format。

### 3.3 海报卡片（问题 2 的回答：是，且这么做）

文件生成卡片扩展 poster 形态，与文档卡片同构：

- 过程区：四/五步指示器（同文档卡）——需求理解→文案→底图→合成→变体
- 产物区：**分规格 tab**（朋友圈版/小红书版/抖音版）缩略图预览
- 操作条：打开文件 / **发送到企微**（复用已有按钮与白名单）/ 重新生成 / **换底图**（重跑③）/ **改文案**（重跑④，不重生成底图——省时省钱）

"换底图不改文案、改文案不重生成底图"是把双层架构做成了可独立重跑的两段——这是对"AI 出图不可控"的工程化解法。

### 3.4 三类场景的快捷入口

| 场景 | 触发方式 | 数据来源 |
|---|---|---|
| 节日营销 | proactive 节日引擎**主动建议**："下周中秋，要为门店做一张月饼促销海报吗？"确认即走工作流 | scenario-reminder-engine 已有节假日引擎 |
| 产品/业务宣传 | 对话："给 XX 产品做一张宣传海报，朋友圈尺寸，突出 XX 卖点" | 产品资料可来自上传文档/业务库 |
| 客户问候 | "给客户名单里的重要客户生成中秋问候海报" → 批量个性化（客户名嵌入每张） | 业务库客户/供应商表（已接入语义层） |

### 3.5 对话与技能入口

- 新技能 `poster-designer`（SKILL.md 教 LLM 工作流：先判类型→按模板写文案→底图 prompt→调渲染）；现有 `image-editor`（平台尺寸裁剪/水印）作为下游环节保留
- 语音/文本同链路；"给这篇文章配一张封面图"仍走轻量 image-editor（不是所有配图都需要走完整海报工作流——**轻配图 vs 重海报分层**）

## 七、场景细化：客户上传产品照片 → 酷炫营销海报

### 7.1 设计红线：产品保真

客户照片里的产品是要拿去卖的真实商品。AI 重绘产品本体 = 失真 = 不可用。
**产品照片像素必须原样进入成品**，酷炫感全部来自背景、光效、排版与装饰（专业设计的共识做法：产品摄影 + 后期合成，而非 AI 重画产品）。

### 7.2 流程（六步）

```
① 上传与理解
   用户传产品照 + "做一张酷炫的营销海报"
   → Clarify 补齐：产品名/核心卖点/价格（Brand Kit 自动带联系方式）
   → 尺寸确认（默认朋友圈 1:1，可选 9:16 抖音）
   → 产品位分辨率校验：照片太小时提示"建议换高清图"（诚实原则，不硬放大）

② 产品图预处理（三选一，默认 A）
   A 抠图合成（推荐）：rembg 本地抠图 → 产品主体透明底 PNG
   B 整图排版：不抠图，照片作为版式中的一个素材区块（最保守，适合场景照）
   C 创意融合：Seedream 指令编辑（图生图，"给产品加霓虹光效/放进赛博场景"）
     —— 仅当用户明确要求"把产品融进场景"时使用，卡片须提示"产品细节可能与实物有差异"

③ 底图生成（Seedream）
   按主题生成酷炫背景（霓虹/渐变科技/质感光斑），
   prompt 中声明产品位区域 + 光源方向（与产品照片受光一致，合成才不违和）

④ 排版合成（HTML 四层，playwright 截图）
   L1 底图层：③的 AI 背景
   L2 产品层：②的透明底产品 PNG——CSS 加阴影/倒影/发光描边（视觉效果酷，但像素不改）
   L3 文案层：主标题/卖点/价格/联系方式（Brand Kit 自动带，文字 100% 精确）
   L4 装饰层：几何线条/光斑/品牌色渐变（模板承担"酷炫"的主要工作量）

⑤ 多规格变体：1:1 朋友圈 / 9:16 抖音 一键派生（产品层与文案层复用，仅版式重排）

⑥ 交付：文件卡分规格预览 → 发送到企微
```

### 7.3 对 P0/P1 落地的增补

- 新增依赖：抠图能力（rembg 本地优先；备选豆包图像编辑 API）
- 卡片增补：②步骤呈现"抠图前/后"对比，用户确认后再进③
- 模板增补：产品海报模板需为"产品位"预留区域与光源一致性参数
- 提示原则：产品位最小分辨率校验（如短边 ≥ 800px），不足时明示而不降级处理

### 7.4 "酷炫"从哪来（给老板的预期管理）

酷炫 = 背景氛围（AI 底图）+ 光效装饰（模板）+ 字体与色彩对比（排版）+ 产品阴影/倒影（CSS）。
产品本身永远是你照片里的样子——这正是客户敢把海报发出去的底气。
