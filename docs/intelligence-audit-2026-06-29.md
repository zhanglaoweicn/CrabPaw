# CrabPaw 智能化水平审计

> 2026-06-29 | 回答"每个子系统到底有多智能？"

---

## 什么是"智能"？

不只完成任务。真正的智能是**系统自己变强，不需要人告诉它怎么做**。

分开看每个子系统：

---

## 一、对话智能 ✅✅✅ 成熟

**现在的能力**：Agent 能理解用户意图，自动调用工具，完成多步骤任务。

| 能力 | 实现 |
|------|------|
| 自动选择工具 | ✅ System Prompt 引导 + 86 个工具契约 |
| 浏览器自动化 | ✅ Playwright + CDP 原生点击 |
| 多格式输出 | ✅ PDF/Word/PPT/HTML/图表 |
| 多通道回复 | ✅ 微信/飞书/CLI/GUI 统一 |
| 任务分解 | ✅ Planner → Researcher → Executor → Critic |

**还缺什么**：对话过程中 Agent 能自己判断"这件事太复杂，我应该分解"，但目前触发主要靠正则匹配，不够智能。

---

## 二、记忆智能 ⚠️ 有基础，但不"聪明"

**现在的能力**：

| 能力 | 实现 |
|------|------|
| 存储和检索 | ✅ SQLite + 内存缓存，模糊搜索 |
| 记忆衰减 | ✅ `memory-decay.js` — 30 天半衰期，信任度衰减 |
| 主动记忆 | ✅ `active-memory.js` — 主回复前自动搜索相关记忆 |
| 记忆强化 | ✅ 被重复使用的记忆自动加分 |
| 分层存储 | ✅ warm/hot/cold 三层 |

**但智能吗？不。**

```
现在的记忆系统 = 一个带自动清理的数据库
它不会：
  ❌ 自动从对话中提取重要信息（需要 Agent 手动调 recall）
  ❌ 发现矛盾并提醒（用户今天说喜欢 Python，三个月前说讨厌 Python）
  ❌ 主动追问模糊信息（"你刚才提到你公司，能告诉我是哪家吗？"）
  ❌ 跨会话关联（上次聊的是项目A的预算，这次聊项目A的进度，记忆应该自动关联）
  ❌ 遗忘原因可解释（为什么这条记忆衰减了？没有日志）
```

**一句话**：记忆系统存得住、取得出，但不会"主动思考"。

---

## 三、工作流智能 ⚠️ 能执行，不灵活

**现在的能力**：

| 能力 | 实现 |
|------|------|
| 条件判断 | ✅ `_evaluateConditions()`——基于输入参数的分支 |
| 循环执行 | ✅ 循环检测保护 |
| 并行执行 | ✅ `executeToolCallsConcurrent()` |
| 步骤编排 | ✅ DAG 拓扑排序 |

**但智能吗？不。**

```
现在的工作流 = 一个预定义的流程图
它不会：
  ❌ 执行中意外失败时自动重规划（步骤3失败了，能跳过或替代吗？）
  ❌ 根据执行结果动态调整后续步骤
  ❌ 学习哪种执行路径更高效
  ❌ 发现某个步骤总是失败，建议修改工作流定义
```

**一句话**：工作流是"死的"——定义好什么就执行什么。不会在执行中学习或调整。

---

## 四、子智能体协同 ⚠️ 能分工，不协同

**现在的能力**：

| 能力 | 实现 |
|------|------|
| 任务委派 | ✅ SpawnSubagent，7 种原型 |
| 分层架构 | ✅ CHAT → REASONING → WORKER |
| 上下文隔离 | ✅ 每个子智能体独立上下文 |
| 结果审查 | ✅ Critic 子智能体 |

**但智能吗？不够。**

```
现在的子智能体协同 = 主Agent派活 → 子Agent干活 → 返回结果
它不会：
  ❌ 子智能体之间直接通信（只能通过主Agent中转）
  ❌ 动态决定"这个任务需要几个子智能体"
  ❌ 子智能体发现"这个任务我不适合，建议换 code_executor"
  ❌ 子智能体之间共享发现（A发现了一个重要信息，B不知道）
  ❌ 子智能体执行质量自动评估和学习
```

**一句话**：像一个老板给员工派活，但员工之间不说话，老板也不知道谁擅长什么。

---

## 五、技能进化 ⚠️ 有进化框架，但进化是"被动的"

**现在的能力**：

| 能力 | 实现 |
|------|------|
| 技能评分 | ✅ Skill scoring |
| 使用追踪 | ✅ skill-usage-tracker |
| 生命周期 | ✅ active → stale → archived |
| 来源追踪 | ✅ skill-provenance |
| 回归检测 | ✅ regression-guard |
| 灰度发布 | ✅ evolution-coordinator (canary→half→full) |

**但智能吗？不够。**

```
现在的技能进化 = 人在看指标 → 人决定改进
它不会：
  ❌ 自动发现"这个技能成功率从 90% 掉到 60%"并自己修
  ❌ 自动从成功对话中提取新模式，更新技能
  ❌ 自动发现"用户问了很多关于X的问题，但没技能能处理"→ 自己创建技能
  ❌ 跨用户学习（用户A的成功经验自动分享给用户B）
```

**一句话**：进化框架建好了，但"进化"的动作还需要人触发。不会自己观察、自己诊断、自己改进。

---

## 六、缺失的智能维度

### 矛盾检测

❌ CrabPaw 没有"矛盾检测"——用户今天说预算 10 万，下周说预算 20 万，系统不会提醒"你之前说的是 10 万"。

### 预测性帮助

❌ 不会预测"基于你过去的行为，你可能需要... "。Amazon 会推荐商品，CrabPaw 不会推荐技能或工具。

### 元认知

❌ Agent 不会反思自己做得好不好。没有"上次这个任务我花了 5 步，这次可以优化到 3 步"。

### 多用户/团队学习

❌ 基于单个用户的记忆，无法形成团队知识。用户A在 CrabPaw 上积累的经验不会帮到用户B。

---

## 七、整体评分

```
对话智能:  ⭐⭐⭐⭐⭐  业界领先
记忆智能:  ⭐⭐⭐     能存能取，但不会主动思考
工作流智能: ⭐⭐⭐     能执行，不灵活
协同智能:  ⭐⭐⭐     能分工，不协同
技能进化:  ⭐⭐⭐     框架好，但被动
矛盾检测:  ⭐         无
预测能力:  ⭐         无
元认知:    ⭐         无
团队学习:  ⭐         无
```

## 八、优先级：下一步做什么

| 优先级 | 做什么 | 为什么 |
|--------|--------|--------|
| ⭐⭐⭐⭐⭐ | **记忆主动化** — 让记忆系统从"被动存取"变成"主动关联" | 这是所有其他智能的基础。没有聪明的记忆，就谈不上学习和进化 |
| ⭐⭐⭐⭐ | **子智能体协同** — 子Agent之间直接通信 + 主Agent动态分配 | 复杂任务的完成质量瓶颈就在这里 |
| ⭐⭐⭐ | **技能自动进化** — 从"人看指标→人改"变成"系统检测→系统改→人批准" | 进化框架已有，就差自动化这一步 |
| ⭐⭐ | **工作流自适应** — 执行中失败时自动重规划 | 对生产环境影响最大，但改动也最大 |
| ⭐ | **矛盾检测/预测** | 锦上添花，但不是当前瓶颈 |

---

*核心结论：CrabPaw 的"自动化"已很强（能自己完成复杂任务），但"自适应"还弱（不会自己发现自己变差、不会从经验中学习）。下一阶段的关键不是加功能，是让已有功能变"聪明"。*
