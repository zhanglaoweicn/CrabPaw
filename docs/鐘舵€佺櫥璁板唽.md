# bossagent 状态登记册（State Registry）v1.0

> 2026-09-03 · Runtime 优化轮 P0-1 · 依据《深入理解 Agent Harness 与 Agent Runtime》规则 3：
> **认知状态（Harness）与执行状态（Runtime）必须使用不同的存储、不同的保留周期、不同的清理策略、不同的备份机制。**
>
> 本册逐格盘点系统里每一类持久化/内存状态的：归属层、存储位置、TTL、进程死后命运。
> 任何新增状态必须先在本册登记（PR 检查项），填不出的格子就是一次未来事故的预演。

路径约定：`DATA_DIR` = `data/.crabpaw`（可被 `CRABPAW_DATA_DIR` 重定向）。

---

## 三、内存态（进程生命 = 状态生命，by design）

| 状态 | 模块 | 丢失后果 | 兜底 |
|---|---|---|---|
| 中断注册表（AbortController per user） | request-interrupt | 在飞 LLM 流失去取消入口 | 流自然结束/空闲 120s 超时 |
| run 活跃内存索引 | run-store `_active` Map | getActiveRunByUser 查不到 | 磁盘 runrec 仍可读（loadRecord 回退） |
| run 用量收集器 | run-usage | 未完成 run 的用量丢失 | 已完成 run 已随 runrec 落盘 |
| SSE 重放环 | sse-broadcast | 断线补发窗口清零 | 磁盘 stream.jsonl 启动恢复 |
| 审批挂起 Promise | registry/approval | 等待中的审批随进程死 | pending 落盘恢复审批卡；run 已被崩溃恢复标记 interrupted |
| HarnessEventBus replay | events.js（1000 条） | 调试回放丢失 | 无（可观测性辅助，可接受） |

## 五、待治理项（本册盘点发现的债务）

1. **`data/` 根散落无主文件**：`tmp_scene2.json`、`tmp_stock.json`、`.piper.json`（0 字节外部工具残留）、`jarvis-candidates/`（音频素材）——无归属、无 TTL，建议一次性归位或清理。
2. **三套会话历史副本**：主存/FTS/unified 的写路径一致性靠代码自律，无对账——P1 #7 记忆归并的第一刀。
3. **工作流定义在 `~/.crabpaw`**：游离于 DATA_DIR 治理之外，备份/重定向（CRABPAW_DATA_DIR）不覆盖它。
4. **session 级审批授权重启丢失**：by design，但应在审批卡 UI 上明示"本次会话有效"。

## 六、变更纪律

- 新增任何持久化状态：先在本册加行（归属层/位置/TTL/死后命运四格必填），随 PR 评审。
- 新增内存态：必须在本册第三节登记"丢失后果 + 兜底"，无兜底项需评审接受。
- 每季度对照本册跑一次实测（文件是否存在、TTL 是否生效），漂移即修。
