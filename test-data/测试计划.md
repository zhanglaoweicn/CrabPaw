# CrabPaw 全面测试计划（2026-09-07）

基于当前分支 `codex/biz-cards-foundation` 的业务逻辑与功能定位编写。配套测试数据全部在
`test-data/` 目录下，用例中直接引用文件名即可。

---

## 一、范围与目标

| 维度 | 内容 |
|---|---|
| 测试对象 | 桌面端（Electron GUI）+ 后端对话链路 + 业务卡 + 数据导入/语义层 + filegen 文档生成 + 主动告警 |
| 测试类型 | 以人工验收/E2E 为主（项目无独立 e2e 目录），单测与 eval 已由 CI 覆盖（jest 169 文件 + evals 58 套件） |
| 通过标准 | 每条用例的"预期结果"全部满足；发现的问题按 P0（功能不可用）/P1（结果错误）/P2（体验问题）分级记录 |
| 已知验证点 | 本轮刻意内置了历史 bug 的回归用例（见 §六），务必逐条核对 |

## 二、环境准备

1. 后端：根目录 `npm run dev`（默认端口，可用 `curl http://127.0.0.1:3000/api/health` 类探活确认）。
2. 桌面端：另开终端 `cd gui && npm run dev:desktop`。dev 模式下 Electron 不会自起后端，必须先起后端。
3. 确认 AI profile 已配置可用模型；Lark/WeCom 通道如未配真实 appId，通道类用例标记 SKIP。
4. 上传入口：GUI 对话框附件上传（走 `upload-handler`）或对话中说"导入这个文件"。

## 五、执行顺序建议

1. 先跑 §四.A（导入是一切业务卡的前置）→ §四.B（业务卡）→ §四.C（巡检/ack）。
2. 再跑 §四.D（filegen/HTML 可视化，重点 D2/D3）。
3. E/F 随主流程穿插观察；G 按环境配置选做。
4. 全程保持后端日志窗口开启，异常时记录时间戳便于定位。

## 六、历史回归坑（本轮必须复验）

- 非 ISO 日期（`2024/01/15`）静默漏数 → A2 专项验证。
- 应收提醒 30min 去重咬合无 ack 态全天播 → C2 验证"今日不再"真正生效。
- 恢复消息不命中 filegen 双闸 → E5 验证。
- panel-handler 入口守卫挡 `/api/proactive` 成 404 死分支 → C1/C2 若 404 先查守卫。
- 搜索场景 `\b` 中文 bug → E1 新闻提问需返回完整搜索结果而非过简回答。
- jest 全量跑需 `--forceExit`；多会话并行时注意 WIP 隔离，避免 stash 事故。

### where.exe cmd 窗口风暴（2026-09-08，用户报告）

- **where.exe 是什么**：Windows 系统自带命令（按名字定位可执行文件），无害。风暴源头 = `src/core/skills.js:232` 技能依赖探测：每个技能加载时对其 bins 依赖跑一次 `where`，且 `execFileSync` 未加 `windowsHide` → 每次探测弹一个可见 cmd 窗口。
- **为何"无限重复"**：两层叠加——①当天多次 `npm run dev` 留下竞争的 watch 实例；②开发期高频源码变更触发 watch 重启，每次重启全量重扫 89 个技能 → where.exe 成串弹。
- ✅ 已修：execFileSync 加 windowsHide:true（探测永久静默）；清理竞争实例，恢复单实例运行。
- 教训：**dev 期高频改码 + watch 重启 + 无 windowsHide 的子进程探测 = cmd 窗口风暴**；同类 spawn（rembg 探测等）已用 windowsHide。
