# B站浏览器兜底操作手册

> **本文件仅当 API 工具（BilibiliSearch/BilibiliPlay）不可覆盖时使用**，例如：专栏文章、用户资料/动态、点赞/投币/三连/收藏、直播交互、登录态操作。内容来自 browser-harness domain-skills/bilibili/navigation.md 实测记录，视角已转换为 bossagent 的 BrowserControl/WebFetch 工具。

## Do this first

- 确认目标是否需要登录：公开页面（视频/搜索/热门/分区列表）先试 WebFetch；专栏 `bilibili.com/read/*` 与空间页必须走 BrowserControl（Playwright 渲染）
- 登录态检测：页面加载后查头像元素——已登录 `.header-entry-avatar` 存在；未登录 `.header-login-entry` 可见
- 抓取前先 `wait_for_selector` 等首屏元素，SPA 路由变化后再等一次

## Workflow

1. 需要登录的场景先确认当前会话已登录（检测 `.header-entry-avatar`），未登录则告知用户需要登录或无法代办，**不要尝试绕过登录**
2. 视频页操作：`wait_for_load()` 不够——播放器与工具条是 load 后异步水合，需额外等待（`wait_for_element('.video-like')` 或固定等待）
3. 抓列表：先滚动加载再取数据（无限滚动页面 `scroll_collect` 容器选 `.feed-card` / 搜索结果 `.bili-video-card`，字段映射 title/a→链接/UP主/播放量）
4. 取到 bvid 后切回 API 链路：`SceneMedia(id="video_1", bvid=...)` 走直链播放

## Why not 替代方案

- **为什么不用普通 http_get 抓专栏/空间页**：bilibili.com/read 和 space.bilibili.com 是 Playwright 渲染站点，服务端只返回空壳 HTML；必须浏览器渲染后取 DOM
- **为什么不用 BilibiliSearch 拿用户动态/三连状态**：搜索 API 只有视频/用户/番剧索引，没有动态流与互动状态接口
- **为什么不要用 `js()` 直接调播放接口**：playurl API 需要正确 Referer/UA 且受 qn 限流，BilibiliPlay 工具已封装降级链，直接复用

## Gotchas

- **三连（长按点赞）= 点赞+投币+收藏一次完成**；投币每视频最多 2 枚，硬币每日领取，**硬币 ≠ B币**（B币为现金充值，用于充电/大会员）
- **"动态"歧义**：`t.bilibili.com` 是关注 feed，`space.bilibili.com/{mid}/dynamic` 是单个用户动态，两者不同页
- 收藏夹 URL 会重定向到 `?fid={DEFAULT_FOLDER_ID}&ftype=create`，属正常
- 视频 URL 从已登录会话点入会带 `?vd_source=` 追踪参数，展示/转发前可剥离
- 部分分区 slug 是缩写：鬼畜=kichiku、娱乐=ent、科技=tech（见 partitions.md），不要猜全拼
- 稍后再看 ≠ 观看历史：`watchlater/#/list` 是独立 SPA 路径
- 历史页若显示"历史功能暂停中"，是用户手动暂停了记录，点击"继续记录历史"恢复
