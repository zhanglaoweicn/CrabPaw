# Prompt Engineering Expert

提示工程专家技能，提供全面的提示优化和自定义指令设计指导。

## 核心能力

| 能力 | 说明 |
|------|------|
| **提示最佳实践** | 清晰、直接的提示编写指导，结构和格式规范 |
| **自定义指令设计** | 创建高效的系统提示和代理指令 |
| **提示优化** | 分析、改进现有提示以提升性能 |
| **高级技术** | 思维链提示、少样本学习、XML 标签、角色提示 |
| **评估测试** | 开发测试用例和成功标准 |
| **反模式识别** | 识别和纠正常见提示错误 |

## 使用场景

- 优化模糊或无效的提示
- 创建特定领域的系统提示
- 设计 AI 代理和技能的自定义指令
- 提高提示的一致性和可靠性
- 调试提示性能问题
- 创建可复用的提示模板

## 核心原则

### 1. 清晰与直接
- **明确表达**：准确说明需要完成的任务
- **避免歧义**：使用精确的语言
- **具体示例**：展示而非仅描述
- **逻辑结构**：按层次组织信息

### 2. 简洁性
- **尊重上下文窗口**：保持提示聚焦相关内容
- **消除冗余**：删除不必要的重复
- **渐进式披露**：按需提供详细信息
- **令牌效率**：平衡质量和成本

### 3. 适当的自由度
- **定义约束**：设定清晰的边界
- **指定格式**：明确输出格式要求
- **设定范围**：定义包含和排除的内容
- **平衡灵活性**：允许推理空间同时保持控制

## 高级技术

### 思维链提示 (Chain-of-Thought)

鼓励逐步推理复杂任务：

```
让我们一步步思考：

步骤 1：首先识别...
步骤 2：然后分析...
步骤 3：最后得出结论...

因此：[结论]
```

### 少样本学习 (Few-Shot)

使用示例引导行为：

```
示例 1："很棒的产品！" → 正面
示例 2："不好用" → 负面
示例 3："还可以" → 中性

现在分类："还不错" →
```

### XML 标签结构

使用 XML 标签组织提示：

```xml
<task>
  <objective>要完成的目标</objective>
  <constraints>限制和规则</constraints>
  <format>期望的输出格式</format>
</task>
```

### 角色提示

分配专业角色：

```
你是一位资深提示工程师，拥有深厚的 AI 系统知识。
你的任务是...
```

## 提示结构最佳实践

### 命名规范
- 使用**动名词形式**：`analyzing-financial-statements`
- 使用**小写连字符**：`prompt-engineering-expert`
- **描述性**：名称应表明能力
- 避免**通用名称**：具体说明领域

### 有效描述
- **第一行**：清晰简洁的摘要（最多 1024 字符）
- **具体性**：指明确切能力
- **用例**：提及主要应用场景
- **避免模糊**：不使用"帮助"或"协助"

## 常见问题解决

| 问题 | 解决方案 |
|------|----------|
| 输出不一致 | 添加格式规范 + 示例 |
| 幻觉/虚假信息 | 要求引用来源 + 置信度 |
| 回答模糊 | 添加具体细节 + 示例 |
| 回答过长/过短 | 指定字数 + 格式 |
| 格式错误 | 展示确切格式示例 |
| 拒绝回答 | 澄清合法目的 |
| 提示过长 | 删除不必要上下文 |
| 无法泛化 | 使用变量 + 处理变体 |

## 调试工作流

1. **识别问题** - 什么不工作？如何失败？
2. **分析提示** - 目标清晰？指令具体？上下文充足？
3. **测试假设** - 尝试添加上下文、更具体、提供示例
4. **实施修复** - 更新提示，测试多种输入
5. **验证结果** - 是否工作？是否泛化？是否高效？

## 反模式警告

### ❌ 模糊提示
```
"分析这个数据，告诉我你的想法。"
```

### ✅ 改进提示
```
"分析这份销售数据，识别：
1. 表现最好的 3 个产品（按收入）
2. 季节性趋势（月度变化）
3. 客户终身价值最高的细分市场

格式化为结构化报告：
- 执行摘要（2-3 句）
- 关键指标表格
- 趋势分析及支持数据
- 可操作建议"
```
