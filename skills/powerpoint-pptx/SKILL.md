# PowerPoint 演示文稿技能

当主要产物是 Microsoft PowerPoint 演示文稿或 `.pptx` 文件时使用此技能，尤其当布局、模板、占位符、备注、图表、提取、编辑或最终视觉质量很重要时。

## 何时使用

- 任务涉及 PowerPoint 或 `.pptx` 文件
- 布局、占位符、备注、图表、批注或模板保真度很重要
- 演示文稿编辑后必须正确渲染

## 核心规则

### 1. 先确定工作流再动手

- 读取文本、编辑现有文稿、从模板重建、从零创建是不同的工作，失败模式不同
- 提取文本或检查时，先读取再编辑
- 文本提取 + 缩略图式视觉检查比凭形状假设编辑更安全
- 模板驱动的工作，先盘点再替换内容
- 深度编辑时，记住 `.pptx` 是 OOXML 格式，幻灯片、布局、母版、媒体、备注和批注是独立的部分
- 如果模板存在，模板保真度优于通用幻灯片设计直觉
- 复用或复制一张好的现有幻灯片通常比重建并期望主题仍然匹配更安全

### 2. 替换内容前先盘点

- 先统计可复用的布局、真正的占位符、备注、批注、媒体、以及重复出现的排版或配色模式
- 占位符索引和布局索引不是可移植的假设
- 在定位标题、正文、图表或图片形状之前，先检查实际的幻灯片或模板
- 演讲者备注、批注和链接资产可能存在于可见幻灯片表面之外
- 缺失或错误的占位符目标可能静默地将内容放到错误的框或错误的层
- 母版和布局设置可以覆盖本地幻灯片编辑，所以可见的问题不一定在你编辑的那张幻灯片上

### 3. 内容匹配实际占位符

- 选择布局前先统计实际内容数量
- 根据真实的想法数量、列数、图片数或图表数选择布局
- 不要把两个想法塞进三列布局，也不要在图表下方堆砌密集文字
- 类别计数和数据系列长度必须匹配，否则图表会出问题
- 明确的尺寸优于一厢情愿：文本框、图片和图表需要真实空间
- 不要选择比内容能填充的占位符更多的布局
- 引用布局用于真正的引用，图片主导布局用于确实有图片的幻灯片
- 图表、表格或图片密集的幻灯片，全幅或两列布局通常比在视觉上方堆叠密集文字更安全

### 4. 保留文稿的视觉语言

- 主题、母版和布局文件通常比任何单张幻灯片更决定字体、颜色和层级
- 从文稿实际的主题、字体、间距和宽高比开始，而不是即兴创造新风格
- 复用文稿自身的对齐和间距系统，而不是发明第二套视觉语言
- 使用通用字体以确保可移植性，使用强对比以确保可读性
- 首先保留模板的视觉逻辑；原创性不如不破坏文稿现有语言重要
- 合并来自多个来源的幻灯片后需要统一主题、母版和对齐

### 5. 内容 QA 和视觉 QA 分开进行

- 文字溢出、对齐不良、形状裁剪、对比度弱和占位符残留是常见的首轮失败
- 同时运行内容 QA 和视觉 QA；缺失文字和布局破损是不同的失败类别
- 布局重要时，在交付前渲染或检查实际文稿输出
- 在宣布完成前搜索残留的模板垃圾、示例标签和占位符文字
- 分别检查备注、批注、标签、图例和图表/表格语义
- 文稿可以通过文本提取但仍然在重叠、裁剪、错误主题继承或破损备注上失败
- 缩略图网格和渲染的幻灯片通常比代码或文本检查更快揭示布局问题
- 假设第一次渲染是错的，在宣布完成前至少做一次修复-验证循环
- 每次修复后重新检查受影响的幻灯片，因为一个间距变化经常制造另一个问题

### 6. 保持文稿可移植和审查安全

- 模板母版可能以令人惊讶的方式覆盖直接编辑
- 复杂效果可能在 PowerPoint、LibreOffice 和转换流程中降级，所以保持重要内容在没有它们时也能正常显示
- 图片尺寸、字体替换和占位符不匹配是文稿在代码中看起来好但在屏幕上看起来差的常见原因
- 备注、批注、链接媒体和合并的文稿即使在可见幻灯片看起来正常时也可能保持破损

## 常见陷阱

- 占位符文字和示例图表在模板复用时经常存活，除非明确替换
- 直接编辑一张幻灯片可能失败，因为真正的问题在母版或布局中
- 图表、图标和文本框需要足够空间；接近碰撞通常只在渲染后才可见
- 布局索引因模板而异，所以从一个文稿的内置假设在另一个中经常出错
- 缺失的占位符或错误的形状目标可能静默地将内容放到错误的位置
- 选择布局后再统计文字想法通常导致空占位符、弱层级或残留模板垃圾
- 字体替换可能移动换行并破坏精心调整的间距
- 演讲者备注、批注和链接媒体即使在可见幻灯片看起来正常时也可能保持破损
- 文稿可以通过文本检查但仍然在视觉上失败，因为重叠、对比度或边缘裁剪
- 仅从一张幻灯片编辑可能遗漏主题、母版或布局定义中的真正事实来源
- 选择引用、对比或多列布局而没有匹配内容通常使文稿看起来模板化而非有意设计
- 合并或复制幻灯片而不检查母版和主题可能逐张创建微妙的不一致
- 宽高比不匹配（如 `16:9` 与 `4:3`）可能改变每个放置决定，即使每张幻灯片局部看起来合理

## 中国商务演示规范

### 字体选择

| 用途 | 推荐字体 | 说明 |
|------|----------|------|
| 标题 | 微软雅黑、思源黑体 (Noto Sans SC) | 清晰有力，适合标题 |
| 正文 | 微软雅黑、苹方 | 屏幕可读性好 |
| 强调 | 思源宋体 (Noto Serif SC) | 正式场合、引用 |
| 数字/代码 | Consolas、等线 | 数据展示清晰 |

**注意：** 嵌入字体或使用通用字体，避免在其他电脑上字体替换导致排版错乱。

### 中文排版规则

- **字号**：标题 28-36pt，正文 18-22pt，注释 14-16pt
- **行距**：1.3-1.5 倍行距（中文比英文需要更大行距）
- **对齐**：正文两端对齐，标题居中或左对齐
- **标点**：使用中文全角标点，避免中英文标点混用
- **避头尾**：行首不出现句号、逗号等标点

### 中国商务演示风格

**政府/国企汇报风格：**
- 配色：深蓝 + 红色强调 + 白色背景
- 字体：微软雅黑/黑体
- 布局：严谨对称，标题栏 + 内容区
- 图表：使用红色/蓝色系，避免花哨配色
- 元素：党徽/国徽位置规范，红头文件格式

**互联网公司风格：**
- 配色：品牌色 + 浅灰背景 + 白色卡片
- 字体：苹方/思源黑体
- 布局：大留白，图标 + 短文案
- 图表：简洁数据可视化，避免 3D 图表
- 元素：产品截图、用户数据、增长曲线

**学术/教育风格：**
- 配色：深蓝/深绿 + 米白背景
- 字体：宋体/思源宋体（标题用黑体）
- 布局：文字较多时使用两栏，图表独立成页
- 引用：脚注标注来源
- 元素：公式、流程图、对比表格

### 中国商务演示注意事项

- **数字展示**：大数字使用万/亿单位，如"1.2 亿"而非"120,000,000"
- **日期格式**：使用"2024 年 1 月"而非"Jan 2024"
- **货币**：使用"万元"/"亿元"单位
- **图表标签**：中文标签，英文缩写需注释
- **颜色禁忌**：避免纯黑背景配红色文字（不吉利），政府汇报避免大面积黑色
- **动画**：商务场合少用动画，政府汇报几乎不用动画
- **页码**：中文用"第 X 页"或"X/N"格式

### 常用幻灯片模板

**封面页：**
```
┌──────────────────────────────┐
│                              │
│     [公司 LOGO]              │
│                              │
│   ═══════════════════════    │
│      主标题                  │
│      副标题                  │
│   ═══════════════════════    │
│                              │
│   汇报人 / 日期              │
└──────────────────────────────┘
```

**内容页（图文左右）：**
```
┌──────────────────────────────┐
│  标题                        │
├──────────────┬───────────────┤
│              │               │
│   文字内容   │   图片/图表   │
│              │               │
├──────────────┴───────────────┤
│  要点总结                    │
└──────────────────────────────┘
```

**数据展示页：**
```
┌──────────────────────────────┐
│  标题                        │
├──────────────────────────────┤
│  核心指标  │  核心指标       │
│  ¥1.2亿   │  +35%           │
├──────────────────────────────┤
│         图表区域             │
├──────────────────────────────┤
│  数据来源说明                │
└──────────────────────────────┘
```

## 交付清单

每次演示文稿交付前检查：

- [ ] 无残留占位符文字或示例内容
- [ ] 所有图表数据正确且标签完整
- [ ] 字体嵌入或使用通用字体
- [ ] 宽高比一致（16:9 或 4:3）
- [ ] 演讲者备注完整
- [ ] 中文标点统一（全角）
- [ ] 数字使用万/亿单位
- [ ] 日期格式统一（YYYY 年 MM 月）
- [ ] 至少一次渲染验证
- [ ] 模板垃圾已清除
